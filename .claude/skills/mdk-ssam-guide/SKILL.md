# MDK SSAM Guide

Rules, conventions, and templates for working on SAP Asset Manager (SSAM) MDK projects.
Non-negotiable — violating them breaks the base product or makes upgrades impossible.

---

## Folder structure rules (hard constraints)

```
WorkspaceRoot/
  SAPAssetManager/          <- READ ONLY — never modify or generate files here
    Application.app
    .project.json
    Pages/ Rules/ Actions/ Services/ i18n/
    <CUSTOM_NAME>.cim       <- CIM lives in ROOT of SAPAssetManager/ (not inside Z project)

  <CUSTOM_DIR>/             <- ALL custom code goes here (name derived from CIM)
    Pages/ Rules/ Actions/ i18n/
    .project.json           <- generated by mdk-create
    Application.app         <- generated by mdk-create
```

| Rule | Why |
|---|---|
| Never write to SAPAssetManager/ | Gets overwritten on every SSAM upgrade |
| Always implement in <CUSTOM_DIR>/ | Upgrade-safe |
| Never copy-paste from SAP and edit in-place | Use override pattern instead |
| Always add CIM entry for every new file | Missing = not registered = silent failures |

---

## How to read SAPAssetManager for reference

Use Read, Glob, Grep tools — never bash:
- Find a file: Glob: SAPAssetManager/Rules/**/*WorkOrder*.js
- Search content: Grep: "functionName" in SAPAssetManager/Rules/
- Read a file: Read: SAPAssetManager/Rules/WorkOrders/WorkOrders_Detail.js

Never modify what you read.

---

## Override pattern — implementing an enhancement

1. Find the SAP standard file using Glob/Grep in SAPAssetManager/
2. Read it to understand the structure
3. Create your override in <CUSTOM_DIR>/ at the same folder path:
   - SAP original:  SAPAssetManager/Rules/WorkOrders/WorkOrders_Detail.js
   - Your override: <CUSTOM_DIR>/Rules/WorkOrders/WorkOrders_Detail.js
4. Write only to <CUSTOM_DIR>/ using Write tool
5. Add CIM entry immediately

## Z naming conventions

Custom project names are always prefixed with Z:
- ZEquinorSSAM, ZCustomSSAM, ZMyCompanySSAM
- Always detect the actual name from CIM IntegrationPoints[].Source at runtime
- Never hardcode a Z project name

## Z project creation (new project from scratch)

When <CUSTOM_DIR> does not exist yet:

Step 1 - Scaffold top-level folders from SAPAssetManager:
```javascript
const fs = require("fs"), path = require("path");
for (const e of fs.readdirSync(sapDir, { withFileTypes: true }))
  if (e.isDirectory()) fs.mkdirSync(path.join(customDir, e.name), { recursive: true });
```

Step 2 - Copy .service.metadata:
```javascript
const src = path.join(sapDir, ".service.metadata");
const dst = path.join(customDir, ".service.metadata");
if (fs.existsSync(src)) fs.copyFileSync(src, dst);
```

Step 3 - Generate real MDK structure via MCP:
```
mcp__mdk__mdk-create {
  "folderRootPath": "<customDir>",
  "scope": "project",
  "templateType": "base"
}
```
Generates: .project.json, Application.app, Pages/, Actions/, Rules/, i18n/

Step 4 - Create CIM file in SAPAssetManager/:
```javascript
const cimPath = path.join(sapDir, customName + ".cim");
if (!fs.existsSync(cimPath))
  fs.writeFileSync(cimPath, JSON.stringify({ IntegrationPoints: [] }, null, 4));
```

## CIM file — format and management

CIM lives in SAPAssetManager/ root. JSON format:

```json
{
  "IntegrationPoints": [
    {
      "Source": "/<CUSTOM_DIR>/Rules/WorkOrders/WorkOrders_Detail.js",
      "Target": "/SAPAssetManager/Rules/WorkOrders/WorkOrders_Detail.js"
    }
  ]
}
```

- Source — path to your custom file
- Target — SAP standard file it overrides

Add entry for every new file:
```javascript
const cim = JSON.parse(fs.readFileSync(cimFile, "utf8"));
cim.IntegrationPoints.push({
  "Source": "/<CUSTOM_DIR>/Rules/WorkOrders/NewRule.js",
  "Target": "/SAPAssetManager/Rules/WorkOrders/NewRule.js"
});
fs.writeFileSync(cimFile, JSON.stringify(cim, null, 4));
```

## CIM integrity check

```javascript
// node /tmp/cim_check.js "<cimFile>" "<customDir>"
const fs = require("fs"), path = require("path");
const [,, cimFile, customDir] = process.argv;
const cim = JSON.parse(fs.readFileSync(cimFile, "utf8"));
const registered = new Set((cim.IntegrationPoints||[])
  .map(ip => path.basename(ip.Source||"", ".js")));
const rules = [];
function scan(d) {
  if (!fs.existsSync(d)) return;
  for (const e of fs.readdirSync(d, { withFileTypes: true })) {
    if (e.isDirectory()) scan(path.join(d, e.name));
    else if (e.name.endsWith(".js")) rules.push(path.basename(e.name, ".js"));
  }
}
scan(path.join(customDir, "Rules"));
console.log("Missing from CIM:", rules.filter(r => !registered.has(r)));
console.log("Stale CIM entries:", [...registered].filter(r => !rules.includes(r)));
```

## Post-customization checklist

- [ ] All new files in <CUSTOM_DIR>/ only
- [ ] Every new .js rule has a CIM entry (Source + Target)
- [ ] No files modified in SAPAssetManager/
- [ ] mcp__mdk__mdk-manage { "operation": "validate" } -> 0 errors
- [ ] Import paths use correct relative paths to SAPAssetManager/
